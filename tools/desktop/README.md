# GA107 언락 확인 앱

KDE 앱 메뉴와 바탕화면에서 실행하고 로그인 시 자동 검사할 수 있는 PySide6 앱이다. 현재 커널의 SS0·SS1 설정이 이번 부팅에서 적용됐는지 확인한다. 로그인 시에는 상태 조회만 수행하며, 언락 모듈 빌드·설치·GPU 설정 변경·재부팅은 자동 실행하지 않는다.

## 성능 벤치마크

기존 `.desktop` 아이콘으로 앱을 열고 **레지스터 MMA 실행**을 누른다. 실행 아이콘은 같은 `app.py`를 가리키므로 재설치할 필요가 없다. 로그인 자동 검사에서는 벤치마크를 실행하지 않는다.

- FP16·BF16·TF32 입력과 FP32 누산, INT8 입력과 INT32 누산을 각각 1·4·8개 독립 누산 체인으로 측정한다.
- 입력을 레지스터에 고정하여 반복 연산 중 전역·공유 메모리 입력 로드를 하지 않는다. 마지막 결과 저장과 커널 실행 오버헤드는 포함된다. 로컬 메모리 사용이 검출되면 측정을 거절한다.
- 300ms 이상 예열 후 7회 측정의 중앙값(ms), 부동소수점 TFLOP/s 또는 INT8 TOPS, 스레드당 레지스터 수, 계산 출력 오차를 표시한다. 메모리 대역폭·일반 GEMM 테스트는 포함하지 않는다.
- `nvidia-smi`로 측정 구간의 SM 클럭을 조회해 범위·평균·샘플 수와 추정 ops/SM/clock을 표시한다. INT8은 같은 평균 클럭에서의 dense 이론 처리량(2048 ops/SM/clock)과 실측 비율도 표시한다. 조회가 실패하거나 측정 구간 안에 샘플이 없으면 비교 불가로 표시한다. 샘플 평균은 모든 순간의 클럭을 보장하지 않는다.
- 결과는 **성능 벤치마크** 탭에만 표시하며 JSON 등 결과 파일로 저장하지 않는다. 출력값으로 언락 성공·실패를 판정하지 않는다.
- 클럭·전력·언락 설정은 변경하지 않는다. 자동 클럭 변화나 다른 GPU 작업은 수치에 영향을 줄 수 있다.

시스템 CUDA Toolkit의 `nvcc`가 PATH에 필요하다. 첫 실행 또는 소스 변경 시 기존 `bench/mma/run.py`의 빌드 기능으로 실행 파일을 컴파일하며, 실행 파일·컴파일 로그·빌드 해시만 `build/`에 남긴다. PyTorch·pynvml·별도 가상환경은 필요 없다. CUDA device 0이 대상 PCI 위치 `0000:01:00.0`이 아니면 측정을 중단한다. 측정 중에는 창을 유지하며 완료 후 닫을 수 있다.

UI 없이 출력만 확인하려면:

```bash
python3 tools/desktop/benchmark.py
```

INT8만 출력하려면 `python3 tools/desktop/benchmark.py --modes int8`을 실행한다.

## 설치

시스템 Python 3와 PySide6를 사용한다. CachyOS에서 PySide6가 없다면:

```bash
sudo pacman -S --needed pyside6
```

저장소 최상위에서 **일반 사용자로** 실행한다.

```bash
python3 tools/desktop/install.py
```

다음 사용자 파일을 등록한다.

- `~/.local/share/applications/ga107-unlock-check.desktop`: 앱 메뉴의 **GA107 언락 확인**.
- `~/.config/autostart/ga107-unlock-check.desktop`: 로그인 후 약 12초 뒤 검사.
- XDG 바탕화면 폴더가 있으면 그 폴더에도 동일한 실행 아이콘을 만든다.

XDG_DATA_HOME/XDG_CONFIG_HOME을 별도 지정했다면 해당 경로를 사용한다. 앱 파일은 이 저장소의 `tools/desktop/app.py`를 가리킨다. 저장소를 이동했다면 설치 명령을 다시 실행한다. Python 가상환경은 필요 없다.

정상 적용 및 버전 일치를 확인한 자동 실행은 창을 띄우지 않고 종료한다. 누락·오류·로그 접근 실패가 있으면 상태와 명령어 창을 띄운다. 수동 실행은 정상 상태에서도 창을 띄운다. 데스크톱 자동 실행은 로그인 후 동작하며, 로그인 전 initramfs의 언락 실행 자체는 기존 부팅 훅이 담당한다.

## 검사 기준

- LG GA107 PCI `10de:25ab`, subsystem `1854:052f`, BDF `0000:01:00.0`인지 확인.
- 현재 커널 버전과 소스·설치·로드된 모듈 버전 비교.
- 현재 모듈의 `execute=Y`, `ss1_full=Y`, 정확한 target 확인.
- 이번 부팅 커널 로그에서 적용 완료와 FLR 후 `SS0=88888888 SS1=00000008` 확인.
- NVIDIA 드라이버 응답과 다음 부팅에 필요한 펌웨어 파일 존재 확인.

부팅 인자나 `.ko` 파일의 존재만으로 적용 성공이라고 판단하지 않는다. 로그를 읽을 수 없으면 확인 불가로 표시한다. 이는 부팅 중 적용과 드라이버 응답의 확인이며, 현재 레지스터를 직접 다시 읽거나 벤치마크를 실행하는 검사는 아니다. 후속 드라이버 동작이 설정을 바꿨는지는 성능 측정 등으로 따로 확인해야 한다.

## 업데이트 명령 사용

창에서 **명령어 전체 복사**를 누르고 터미널에 한 번 붙여넣는다. fish에서도 동작하도록 내부 스크립트를 인용한 `bash -c` 명령이다.

명령은 현재 실행 중인 일반 `linux-cachyos` 커널을 대상으로 다음을 수행한다.

1. 헤더가 없으면 `linux-cachyos-headers` 설치를 요청하고 현재 커널용 헤더가 존재하는지 검사한다. 저장소 패키지와 실행 커널이 달라 헤더가 없으면 중단한다.
2. 모듈 빌드와 vermagic 확인, 현재 커널 경로에 설치, depmod 실행.
3. 펌웨어가 누락됐을 때만 고정 입력 다운로드·해시 검사·추출·펌웨어와 라이선스 설치.
4. 기존 mkinitcpio 순서 훅 설치.
5. 관리자 보조 스크립트로 `/etc/default/limine`의 일반 커널 인자에 target·execute·ss1_full 추가. 원본을 같은 디렉터리에 백업하며 root 인자와 LTS 항목은 유지한다.
6. `limine-mkinitcpio`로 부팅 이미지 갱신.

오류 시 후속 작업을 중단한다. 명령이 끝나도 현재 부팅에는 새 모듈을 로드하지 않는다. 작업을 저장하고 완전히 종료했다가 켠 뒤 다시 검사한다. 전원 종료 명령은 복사 스크립트에 포함하지 않는다. warm reboot·현재 GPU unbind·실행 중 모듈 강제 교체는 수행하지 않는다.

복구용 LTS 등 일반 `linux-cachyos`가 아닌 커널은 자동 복구 명령 대상에서 제외한다. 복잡한 부팅 설정 문법이나 기존 root 인자가 없는 경우에도 자동 편집을 중단하고 수동 확인하도록 안내한다. `configure_boot.py`는 파일 내용을 셸 코드로 실행하지 않는다.

## 진단·제거

창 없이 개인정보를 걸러낸 상태 요약을 확인한다.

```bash
python3 tools/desktop/app.py --check
```

수동 실행:

```bash
python3 tools/desktop/app.py
```

앱 메뉴·바탕화면 아이콘·로그인 자동 실행을 제거한다. 언락 모듈과 시스템 부팅 설정은 제거하지 않는다.

```bash
python3 tools/desktop/install.py --uninstall
```

검사 요약은 `~/.cache/ga107-unlock-check/status.json`에 저장한다(XDG_CACHE_HOME 지원). 커널·버전·상태만 보관하며 hostname·사용자명·UUID·전체 부팅 로그는 저장하지 않는다. 생성되는 `.desktop`은 개인 경로를 포함하므로 저장소에 넣지 않는다. 재현 가능한 설치 스크립트만 Git에 포함한다.
